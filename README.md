# red-kv

Fast embedded KV store (redb-backed) for Bun/Node, distributed as prebuilt
`.node` binaries. Consuming projects never run Rust or `napi build` — the
addon is compiled once, in this repo, ahead of time.

This repo ships exactly two things:

1. **The API layer** (`ts/`) — an npm package exposing `getKvStore(module)`,
   which unwraps the `KvStore` constructor from a `.node` module you've
   already loaded.
2. **The prebuilt binaries** — platform-specific `.node` files, built by
   `.github/workflows/release.yml` and attached to GitHub Releases.

## Using it

Get the prebuilt `.node` file for your platform from the
[Releases](../../releases) page, load it however fits your runtime, then
unwrap the constructor:

```ts
import { createRequire } from "node:module";
import { getKvStore } from "red-kv";

const mod = createRequire(import.meta.url)("/path/to/red-kv.linux-x64-gnu.node");
const KvStore = getKvStore(mod);
const kv = new KvStore("mydb.redb");

kv.put(Buffer.from("key"), Buffer.from("value"));
kv.get(Buffer.from("key")); // Buffer | null
kv.delete(Buffer.from("key")); // boolean
kv.putBatch([{ key: Buffer.from("a"), value: Buffer.from("1") }]); // single-txn bulk write
```

`red-kv` never loads the file itself — that's the consuming project's job
(`createRequire` in Node ESM, native `import` in Bun, a bundler plugin,
etc.). The package just gives you the types and the unwrapper.

You pick the right `.node` file for your platform. The five prebuilt files
are `red-kv.linux-x64-gnu.node`, `red-kv.linux-arm64-gnu.node`,
`red-kv.darwin-x64.node`, `red-kv.darwin-arm64.node`, and
`red-kv.win32-x64-msvc.node`.

Values are raw bytes — serialize on the JS side (`JSON`, `msgpack`, etc.)
before calling `.put()` if you need structured values.

## Installing

```bash
bun add red-kv   # or: npm install red-kv
```

Or just copy `ts/index.ts` + `ts/types.d.ts` into your project — they're
small files with zero dependencies.

## What this repo contains

- `rust/` — the native addon source. `napi build` compiles it to a `.node`
  binary and generates `ts/types.d.ts` from the `#[napi]` declarations
  (never hand-written). Its CI builds all 5 targets.
- `ts/` — the npm package: `index.ts` (the types + `getKvStore` unwrapper)
  plus the generated `types.d.ts` that ships alongside it.

`ts/types.d.ts` is a build artifact — generated by `napi build` from
`rust/src/lib.rs` and git-ignored. The npm `files` whitelist includes it,
so it's always in the published tarball.

## Developing / rebuilding the native addon

Only relevant if you're changing `rust/src/lib.rs` itself:

```bash
cd rust
bun install
bun run build   # napi build --platform --release --dts ../ts/types.d.ts
```

The build compiles for your current host only and regenerates
`ts/types.d.ts`.

Versions are pinned for reproducible builds: `bun` is pinned in
`rust/.bun-version`, Rust is pinned to `1.95.0` in
`rust/rust-toolchain.toml` (read automatically by rustup), and
`rust/Cargo.lock`, `rust/bun.lock`, and `ts/bun.lock` are committed. CI
(`release.yml`) uses the same pins, so a rebuild at any point produces the
same output.

Cross-compiling all 5 targets locally has real OS constraints (macOS
targets need a Mac, `win32-x64-msvc` needs Windows or `cargo-xwin`,
`linux-arm64` needs `cross`) — that's exactly why `release.yml` exists.
Push a `v*` tag and let CI produce all 5 for you.
