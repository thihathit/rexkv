# red-kv API

red-kv is two layers:

- **Native (Rust + redb)** — the `.node` addon. Bytes in / bytes out; serialization (JSON etc.) is the caller's job.
- **TS library (`ts/`)** — a small source-only npm package (`red-kv`) layered on the native bindings: `JsonTable`, the JSON serializer, and helpers.

```
                ┌──────────────────────┐
  your app  ──▶ │  TS library (ts/)    │   JsonTable, serializeJSON,
                │  red-kv npm package  │   deserializeJSON, getKvStore
                └──────────┬───────────┘
                           │  Buffer keys/values
                ┌──────────▼───────────┐
                │  Native .node addon  │   KvStore, KvTable (NAPI-RS + redb)
                │  (Rust bindings)     │
                └──────────┬───────────┘
                           ▼
                      redb database file
```

---

## Part 1 — Native bindings (Rust, exposed as `.node`)

Exports one class: `KvStore` (declared in `ts/types.d.ts`, generated by NAPI-RS). All operations are synchronous and bytes-only.

### `KvStore`

| Member | Signature | Description |
| --- | --- | --- |
| constructor | `new KvStore(path: string)` | Open (or create) a redb database file. |
| `openTable` | `openTable(name: string): KvTable` | Open (or create) a named table. |
| `close` | `close(): void` | Close the database; every later op (store or any table) throws `"database is closed"`. |

### `KvTable`

| Member | Signature | Description |
| --- | --- | --- |
| `name` | `get name(): string` | Table name. |
| `get` | `get(key: Buffer): Buffer \| null` | Fetch value, or `null` if key missing. |
| `put` | `put(key: Buffer, value: Buffer): void` | Insert or overwrite. |
| `delete` | `delete(key: Buffer): boolean` | Remove key; returns `true` if it existed. |
| `remove` | `remove(key: Buffer): boolean` | Alias of `delete`. |
| `putBatch` | `putBatch(entries: KvEntry[]): void` | Insert many entries in one transaction. |

### `KvEntry`

```ts
interface KvEntry { key: Buffer; value: Buffer }
```

### Semantics (native layer)

- Keys/values are raw bytes. Content equality decides a hit; ordering is byte-lexicographic (redb B-tree).
- Every call runs its own transaction; all ops are synchronous.
- Tables share one database file; identical names open the same table.

## Part 2 — TS library (`ts/`, npm package `red-kv`)

Source-only package (`files: ["index.ts", "types.d.ts"]`); re-exports the native types so one import covers both layers:

```ts
import { JsonTable, getKvStore } from "red-kv";
const KvStore = getKvStore(require("./red-kv.linux-x64-gnu.node"));
```

| Member | Signature | Description |
| --- | --- | --- |
| `getKvStore` | `getKvStore(module: unknown): typeof KvStore` | Unwrap the `KvStore` constructor from a loaded `.node` module. |
| `serializeJSON` | `serializeJSON(value: unknown): Buffer` | JSON-encode to bytes, restoring non-JSON types on decode. |
| `deserializeJSON` | `deserializeJSON<T>(bytes: Buffer): T` | JSON-decode bytes from `serializeJSON` (or any JSON). |
| `JsonTable` | `new JsonTable(table: KvTable)` | JSON de/serializer wrapper over a byte table. |
| types | `KvStore`, `KvTable`, `KvEntry`, `JsonKey`, `JsonEntry` | Native types re-exported / library types defined in `index.ts`. |

### `JsonTable<K, V>`

`K extends JsonKey = JsonKey` is the key type (`Buffer`, `string`, or a union), `V = unknown` the value type; `get`/`getOr` return `V` / `V | null`.

| Member | Signature | Description |
| --- | --- | --- |
| `raw` | `readonly raw: KvTable` | Underlying byte table. |
| `name` | `get name(): string` | Table name (delegates to `raw`). |
| `put` | `put(key: K, value: V): void` | `serializeJSON` and store; string keys are utf8-encoded. |
| `get` | `get(key: K): V \| null` | `deserializeJSON` the value; `null` if key missing or value is JSON `null`. |
| `getOr` | `getOr(key: K, fallback: V): V` | Fallback when the key is missing. |
| `putBatch` | `putBatch(entries: { key: K; value: V }[]): void` | Encode and insert in one transaction. |
| `delete` / `remove` | `delete(key: K): boolean` | Passthrough to the byte table. |

`JsonTable` stores serialized bytes, so a value read back with `get` and put back with `put` (even nested inside a larger structure) keeps its full fidelity without re-serializing its internals — see per-level metadata below.

### Serialization (`serializeJSON` / `deserializeJSON`)

- Restores values JSON can't round-trip. A detection pass (single `JSON.stringify` whose replacer reads `this[key]`, the pre-`toJSON` value) finds them and also rewrites values `stringify` can't handle (e.g. `BigInt`); if none are found the pass output is used as-is, with no metadata and no extra work.
- When special values exist, a second pass copies the tree from the original value. Each level (plain object or array) that directly holds one gets one short `"__$p"` metadata key mapping short relative paths (bare property names, plus array indices) to type tags, e.g. `{ "at": "...", "__$p": { "at": "date" } }`. Nested plain objects/arrays in the data serialize as ordinary JSON — their tags are recorded on their own level.
- Levels with no special children are not copied. When the root itself is not a plain object (array, `Date`, `Map`, …) the value is wrapped as `{ "__$p": …, "__$v": … }`. `deserializeJSON` revives deepest paths first, unwraps `"__$v"`, and deletes `"__$p"` after restoring that level.
- Supported types (metadata tag in parentheses): `Date` (`date`), `Buffer` (`buffer`), `Uint8Array` (`uint8array`), `Map` (`map`), `Set` (`set`), `RegExp` (`regexp`), `BigInt` (`bigint`), `NaN` (`nan`), `Infinity`/`-Infinity` (`infinity`/`-infinity`).
- The `"__$p"` and `"__$v"` keys are reserved — passing data that already contains them throws.
- `undefined` is dropped and `null` stays `null`, per JSON semantics.
- `Symbol` values and custom class prototypes are dropped (not JSON-representable and not generically restorable); other typed arrays (e.g. `Int32Array`) serialize via their `toJSON` shape without special restore.
